Architecture Overview

Factory Inventory Management System

A full-stack demo application for inventory management, order tracking, demand forecasting, and spending analytics for factory operations. Vue 3 frontend, FastAPI backend, in-memory JSON data — no database.

Tech Stack

Frontend

Vue 3 + Vite

Composition API, client-side routed SPA, served on port 3000.

  • vue-router for page navigation
  • axios for HTTP calls to the API
  • Composables for shared state (filters, auth, i18n)
Backend

Python FastAPI

REST API with Pydantic validation, served on port 8001.

  • Uvicorn ASGI server
  • CORS enabled for local dev (allow_origins=*)
  • Auto-generated docs at /docs
Data

In-Memory JSON

No database — static JSON files loaded into memory at startup.

  • 7 JSON files in server/data/
  • Loaded once via mock_data.py
  • Changes don't persist across restarts

System Architecture

Request Lifecycle

1

User interacts

A filter or view change updates reactive state in a Vue component or composable (e.g. useFilters).

2

api.js call

The component calls a method on api.js, which builds query params and fires an axios GET.

3

FastAPI route

Uvicorn routes the request to the matching handler in main.py (e.g. /api/orders).

4

Filter + validate

Handler filters the in-memory list (apply_filters, filter_by_month) and validates output via Pydantic.

5

Render

JSON response returns to the component; reactive refs update and computed properties re-render the UI.

Data Flow

All four global filters — Time Period, Warehouse, Category, Order Status — flow the same path for every view:

FilterBar.vue → useFilters composable → api.js (query params) → FastAPI endpoint → In-memory filtering → Pydantic validation → JSON response → Vue refs / computed

Raw data lives in refs (allOrders, inventoryItems); everything derived — totals, chart series, filtered lists — lives in computed() properties so it recalculates only when a dependency changes.
